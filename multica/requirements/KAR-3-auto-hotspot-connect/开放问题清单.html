  • 无法由事实回答、但可以安全默认的，转为显式假设（A-xxx），写明依据与不成立的影响；H1 批准即视为基线。

2. 第 1 轮问题（Q-001…Q-007）

第 1 轮聚焦：问题是什么、谁受影响、范围到哪里、哪些约束不可动。

Q-001 「手动链接」具体指哪一步？ 已收敛

为什么问
这句话可能指车机侧点按、iPhone 侧操作、或开热点，范围差一个量级。
建议默认
只承诺 DiPlay 可控的车机侧：打开应用、点 Connect、选设备、开热点。
不同选择影响
若包含 iPhone 侧蓝牙配对，则超出 DiPlay 能力（非越狱/非 MFi 身份不做），需求不可实现。
收敛结论
车机侧四步。iPhone 的首次蓝牙配对仍由人完成（BR-5）。
依据
人类原话 + docs/CONNECTION_SETUP.md 第 4–5 步 + 项目约章 §1「不做 iPhone 越狱或插件」

Q-002 四种无线后端都要"自动"吗？ 已收敛

为什么问
后端差异会导致验收矩阵膨胀。
建议默认
自动策略对所有已保存后端生效；首发验收以 MANUAL_HOTSPOT 为主，其余做回归。
不同选择影响
全部纳入首发验收会让真车资源需求翻倍；只做一种会让 WIFI_P2P 用户觉得"没修"。
收敛结论
规则统一、验收分级（D-005）。
依据
ConnectionSettingsSection.kt:48-66（MANUAL 为推荐项）+ 约章 §7 优先级

Q-003 自动连接默认开启还是默认关闭？ 转假设 A-002 + 决策 D-002

为什么问
直接决定"默认体验是否等于用户诉求"。
建议默认
首次成功无线连接后默认开启；设置可关闭，关闭后行为等同 0.2.22。
不同选择影响
默认关闭：SM-001 不可达，用户仍要自己找开关；默认开启：属于行为变更，需人类同意（R-002）。
收敛结论
作为假设 A-002 推进，H1 由人类拍板 D-002。
依据
现状四个开关默认全关（DiPlayBootstrap.kt:79-86）

Q-004 哪些时机算"自动"？ 已收敛

为什么问
触发源决定权限依赖与真车测试项。
建议默认
冷启动、打开应用、首选 iPhone 蓝牙到达、休眠唤醒四类；不含 BLE 靠近。
不同选择影响
加入 BLE 靠近需要新扫描与功耗预算，且 DiLink 蓝牙广播不可靠。
收敛结论
四类触发 + 降级阶梯（FR-002），BLE 靠近列为非目标 NG-2。
依据
现有 BootReceiver/PhoneBluetoothReceiver/Activity 三条路径 + 缺失唤醒触发（§2.1）

Q-005 自动连接失败时应该弹窗吗？ 已收敛

为什么问
驾驶场景下弹窗影响安全，也影响"是否算打扰"。
建议默认
不弹全屏阻塞框；Home/启动界面显示原因 + 单一"重试"。
不同选择影响
弹窗更醒目但可能遮挡倒车影像、打断驾驶；不弹则依赖状态可见性（FR-010）。
收敛结论
NFR-011 + FR-007 + FR-010；AC-009、AC-025。
依据
现有失败路径使用 appDialogBuilder；约章 §3 安全优先

Q-006 重试多少次、多久算"尽力"？ 转假设 A-003

为什么问
太少连不上，太多让车主干等且耗电。
建议默认
≤ 5 次、总时长 ≤ 150 s、退避 ≥ 2 s。
不同选择影响
预算过大→等待焦虑；过小→弱信号/慢启动车机误判失败。
收敛结论
写入 NFR-002 / AC-008，H3 实测后可按证据调整。
依据
WirelessStartupPolicy.kt:4-11（5 次、15 s、30 s、60 s）

Q-007 这算连接路径改动吗？风险等级？ 已收敛

为什么问
决定门禁与验证强度。
建议默认
算；S1（连接路径回归）为主，叠加 S2（固件兼容）。
不同选择影响
若按 S3 处理会漏掉真车验证与回归，违反约章 §6。
收敛结论
风险登记 R-001…R-008；H3 真车为硬条件。
依据
约章 §3「连接、音频、HUD、车辆数据类改动，H3 必须真车」+ §6 S1/S2

3. 第 2 轮问题（Q-008…Q-014）

第 2 轮聚焦：边界与异常、权限与数据、非功能、验收与回滚、依赖。

Q-008 热点口令保存吗？存在哪里？ 已收敛

为什么问
自动连接必然要复用已保存的热点凭据，位置决定安全边界。
建议默认
维持现状：应用私有 SharedPreferences，不新增副本。
不同选择影响
改用 Keystore 加密会扩大改动面（NG-6），且当前 allowBackup=false 已阻断备份外泄。
收敛结论
NFR-004；本需求不改存储介质，只约束"不得新增副本/不得外泄"。
依据
AirPlayPersistence.kt:60-61,459-478 · mobile/src/main/AndroidManifest.xml:6 · SettingsBackupCodec.kt:23-40（口令不在白名单）

Q-009 别人能冒连吗？ 已收敛

为什么问
"自动连"容易被理解成"谁都能连"。
建议默认
不改信任模型：热点口令 + iAP2 配对认证双门槛；自动连接只认首选设备。
不同选择影响
若为方便放宽认证，会触及 Apple 认证红线与安全红线（S0）。
收敛结论
NFR-005 + FR-008 + BR-2；开放热点场景列入 H3 检查项。
依据
CarPlayController.kt:2615-2662（只认已配对/已选设备）· docs/WIRELESS_HOTSPOT_JOIN.md

Q-010 首次配对能否也自动？ 已收敛

为什么问
用户说"第一次之后"，但边界需要写死。
建议默认
首次必须显式：选设备、确认热点、接受系统配对提示。
不同选择影响
全自动配对会绕过用户知情与安全确认，且无 App 可用的配对 API。
收敛结论
FR-004 / BR-5；AC-005。
依据
人类原话「第一次链接之后」+ choosePhone() 现有交互

Q-011 没有 ADB 的车主怎么办？ 已收敛

为什么问
开机自启与自动开热点目前都依赖 ADB 授予的权限。
建议默认
降级阶梯：没有 ADB 时至少"打开 DiPlay 即自动连接"成立。
不同选择影响
若把 ADB 当必需，绝大多数车主拿不到本需求的价值。
收敛结论
G-4 + FR-002 阶梯 + AC-002；H3 增加"无 ADB 车机"槽位 V-07。
依据
CarHotspotSetup.kt:20-25,51（权限经 ADB 授予）· docs/CONNECTION_SETUP.md「needs an already-authorized … ADB connection」

Q-012 「休眠唤醒」怎么定义？ 转假设 A-004

为什么问
车机可能熄屏休眠、可能被杀进程、可能直接断电。
建议默认
指未重启的系统/屏幕唤醒；进程被杀不承诺后台恢复，退化为启动触发。
不同选择影响
要求进程被杀也恢复 → 需要常驻前台服务或定时唤醒，触及功耗（NFR-003）与权限（A-007）。
收敛结论
FR-009 + A-004；H3 记录"唤醒方式"。
依据
现有清单仅 BOOT_COMPLETED（AndroidManifest.xml:173-180）

Q-013 有线/ USB 要不要一起改？ 已收敛

为什么问
用户只说"链接"，可能包含有线。
建议默认
不改，只保证不回归。
不同选择影响
扩大范围会显著拉长周期且与"热点"主题无关。
收敛结论
NG-1 + FR-014 + AC-017。
依据
issue 标题「支持自动热点链接」限定无线；约章 §7 优先级

Q-014 车型、固件与语言范围？ 转假设 A-005

为什么问
决定 H3 设备矩阵与翻译工作量。
建议默认
BYD DiLink 3.0/4.0/5.x，Android 7.0+，11 种语言。
不同选择影响
扩大车型→真车资源与 S2 风险上升；缩语言→违反约章 §5.4。
收敛结论
NFR-006 / NFR-007；H3 矩阵 V-01…V-08。
依据
约章 §1、§5.4；docs/COMPATIBILITY.md

5. 假设登记

假设不是"随便填的默认"，每条都有依据与失效影响；H1 批准即成为基线，后续变更走 CR。

ID假设依据不成立的影响
A-001"手动"仅指车机侧人类原话 + 现有设置流程扩展到 iPhone 侧即不可实现
A-002首次成功后默认开启自动连接默认关闭使功能等于不存在SM-001 不可达；需人类接受
A-003≤5 次 / ≤150 s / 退避 ≥2 s沿用既有常量体验或成功率失衡
A-004唤醒不含进程被杀恢复Android 后台限制需常驻服务，触及功耗/权限
A-005DiLink 3/4/5 + Android 7.0+约章 §1、兼容性文档扩大范围需更多真车资源
A-006首选缺失且仅 1 台候选时不自动改连安全优先便利性下降，但避免误连
A-007不新增权限/组件现有权限已覆盖触发若需新权限须 DECISION-REQUEST
