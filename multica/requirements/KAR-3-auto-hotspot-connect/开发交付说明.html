2. 实现摘要与范围对照

自动连接收敛为一条链路：四类触发源 → 纯策略门禁 AutoConnectGate → 唯一状态机 AutoConnectSession（内含 AutoConnectBudget）→ 既有 DiPlayActivity.connect(true) / CarPlay 栈。手动与 USB 路径不改语义，自动路径不弹阻塞框。

7. 部署、开关、回滚与故障处理

  • 无服务端部署；车机端 APK 增量升级。版本号/CHANGELOG/源码 ZIP 由人类发布流程负责。

8. 裁定、偏差与技术债

ID状态结论 / 证据
D-1 宿主预算测试已关闭WirelessStartupRecoveryTest 新增 TC-046（第 6 次许可 null → startupRetryStopped、显示重试）与 TC-047（100 s 仍可重试；150 s 后停止、许可恒 null）；23/23 通过，R-010 由这两条兜住
D-2 休眠唤醒恢复已关闭（按裁定给出显式结论）结论：唤醒事件下，若 DiPlay 的 CarPlay 画面仍在且流健康 → 不做任何事；画面仍在但流已断 → 调用既有 reconnectAfterLoss（受自动预算约束）；画面不在 → 走 offer(SLEEP_WAKE) 开新会话。代码证据：DiPlayActivity.refreshAutoConnectWakeReceiver() 的监听器分流 + CarPlayHostActivity.onWakeRecover()；测试证据：wakeRecoveryOnlyActsOnADroppedStreamItOwns（非 owner / 流健康 / 流已断三路）。真机 P90 ≤20 s 仍归 H3 V-01…V-03
D-3 本机 CI 不可用待外部Actions 未运行（分支 push 不触发：push: main / pull_request / workflow_dispatch）。本机沙盒禁止 JVM 自 attach、Robolectric 临时路径与本地 socket，且 dl.google.com 传输间歇 TLS 重置；本机结果只作补充
D-4 单一"重试"入口已收口（记偏差）Home inline notice 展示失败原因与进度，单一动作复用既有 Connect phone 按钮；不新增独立按钮，记为可接受偏差
D-5 一次性 opt-in 提示已关闭AutoConnectPreferences.takeOptInNotice() 只在 ENABLED_AUTO 且未提示过时返回 true 并置 notice_shown；Home 新增提示行复用既有 settings_auto_connect_enabled_notice（11 套已存在，无新键）；optInNoticeIsShownOnce、disabledUserNeverAutoReenables 通过
D-6 NEEDS_CHOICE 专用页面维持偏差沿用既有 choosePhone()；门禁"不静默选择"不受影响，专用页面待 A4/H3 决定
D-7 TC-010 口径已裁定按 H2 批准的 §7.7：剩余 <20 s 不再开新尝试，149 999 ms → 拒绝 是正确行为；TC-010 的 149 999 ms 期望是测试设计笔误，实现不改，由 KAR-04 回写测试设计

9. Reviewer 指南

  1. autoconnect/AutoConnectGate.kt 与 AutoConnectBudget.kt：纯策略、无 I/O，数值与设计 §6/§7 一致。
  2. AutoConnectSession.kt：终态不可转移、单实例、resetForTest()、诊断写入点。
  3. DiPlayActivity 的 automaticConnectionSettings()、startAutomaticConnection()、唤醒分流：是否绕过门禁、是否可能弹窗、手动路径是否被改。
  4. CarPlayHostActivity.reconnectAfterLoss 的许可分支与 onWakeRecover()：只对自动会话生效，手动 sessionId=null 行为不变。
  5. G-12 两处测试改动：git diff 只应有位置参数与计数拆分，不允许出现被删除的 assert*。
  6. AndroidManifest.xml 零 diff；11 套 strings 占位符一致。
