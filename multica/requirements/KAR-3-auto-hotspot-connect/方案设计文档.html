2.3 非目标（设计层明确不做）

  • DG-N1 不重写连接栈：CarPlayController 的无线启动流程、四种 WirelessHotspotManager、蓝牙 RFCOMM 与 0x5703 凭据下发保持原样。
  • DG-N2 不新增 BLE/RSSI 靠近检测（NG-2）；不做人离开自动断开（NG-7）。
  • DG-N3 不引入协程/Flow/新依赖；沿用现有 Handler、Executors、SharedPreferences 与 Robolectric 测试栈。
  • DG-N4 不做"进程被杀后仍后台恢复"（A-004）；不为此新增前台服务或 JobScheduler。
  • DG-N5 不改发布流程、版本号、CHANGELOG、站点（约章 §9.4）。
  • DG-N6 不在本次改动中重构设置页整体布局；只做 §11 列出的新增与一处卡片内移动。

2.4 设计原则

  1. 单一决策点：所有自动触发先经 AutoConnectGate（纯函数），再进 AutoConnectSession（唯一状态机）。UI 与接收器只做"事件采集"，不做策略判断。
  2. 纯策略 + 薄适配：预算、目标解析、设置可见性、诊断格式写成无 Android 依赖的纯 Kotlin，单测直接跑；Android 适配层只搬运数据。
  3. 附加式改动：现有 DiPlayActivity.connect(wireless)、CarPlayHostActivity.reconnectAfterLoss 只增加分支/截止时间参数，不重排既有调用；手动路径参数为空时行为与 0.2.22 一致。
  4. 失败闭合：没有"再等等"的隐式状态；每个会话结束都有一个可显示的终态与一个可执行动作。
  5. 可观测到字段级：诊断只写枚举/整数/时间戳，可 grep、可断言、不含凭据。

12. 失败、冲突与降级设计

12.1 原则

  1. 先分类再决定重试；不可重试的失败一次也不重试。
  2. 失败不改写任何设置（BR-3），不删除首选设备与热点凭据。
  3. 自动路径不弹阻塞对话框、不覆盖倒车影像；提示可延后或忽略（NFR-011）。
  4. 失败必须可解释（原因 + 下一步），且下一次真实触发可以重新开始。

12.4 冲突处理（SC-008）

  • 触发条件：首选失效（未配对）或本次会话失败且首选不可达而其他 iPhone 已连接。
  • 呈现：`NEEDS_CHOICE` 终态页；首选置灰并注明"已配对 · 不在附近/未配对"；其他候选并列，数量与诊断一致。
  • 选择动作：点击"连接这台" → 在 notice 中已说明"会把它设为新的首选设备"→ 写入首选并开始一次用户发起的会话。不额外加确认对话框（原型 SC-008 的设计；避免多一次点按）。
  • 不静默：无首选、首选失效、≥2 候选时，门禁返回 NeedsChoice；自动会话不会连接任何一台。

12.5 驾驶场景礼貌

  • 失败提示只在 DiPlay 自己的界面（Home / CarPlay 启动界面）出现，不使用 Toast 之外的系统级覆盖；不抢焦点。
  • 正在显示倒车影像/其他应用时，自动会话的失败不主动切前台；用户回到 DiPlay 时看到 inline notice。
  • 自动会话进行中允许一键取消；取消不弹确认（SC-004 的"取消自动连接"）。

ADR-001 首次成功后才默认开启自动连接

状态：已决定（依据 H1 D-002） · 影响：FR-011/012 · 关联 R-002

背景
需求根因是"四个自动化开关默认全关，功能等于不存在"。但直接把 auto_connect 默认改 true 会让老用户升级后行为突变。
选项
(a) 安装即默认开启；(b) 首次成功无线连接后默认开启，可关；(c) 保持默认关闭，只做入口引导。
决定
选 (b)：auto_connect_master 初始 false；首次成功（首帧渲染）后，若 opt_in=NEVER_ASKED 则置 true 并显示一次性提示；用户手动关闭 → DISABLED_USER，永不自动再开。老用户若此前显式开过子开关，迁移为 true（表 5-3）。
后果
满足 D-002 与人类诉求；不改变未成功过的新/老用户行为；多一个持久化状态机与一次性提示；测试需覆盖"两次成功""关闭后再成功"。
复审条件
H3 反馈"默认开启打扰"或车机被盗用风险；或 D-002 被人类改判。

ADR-002 事件驱动，不用轮询找 iPhone

状态：已决定 · 影响：FR-002/009、NFR-003 · 关联 R-004

背景
休眠唤醒与"iPhone 回到车内"没有现成触发；最直接的想法是每 N 秒检查蓝牙/热点。
选项
(a) 前台服务定时轮询；(b) 系统广播 + 生命周期回调（蓝牙 ACL、SCREEN_ON、Activity 启动）；(c) BLE 靠近检测。
决定
(b)。轮询违反 NFR-003 且耗电；BLE 超出 NG-2。休眠唤醒用进程内运行时接收器（ADR-007），不新增清单组件与前台服务。
后果
零额外轮询；代价是"只在系统给事件时才知道"，进程被冻结/回收时可能不触发，作为 R-004 记录并由 T-2 兜底。
复审条件
若 H3 证明目标固件在唤醒时既不发 SCREEN_ON 也冻结接收器，需重新评估（可能要求新增前台服务 → 回 H1）。

ADR-003 自动会话预算：5 次 / 150 s / 2-4-8-16 s

状态：已决定 · 影响：FR-006、NFR-002 · 关联 AC-008

背景
既有 MAX_STARTUP_RETRIES=5 是"5 次重试"（最多 6 次尝试），退避 2 s×2ⁿ、上限 30 s，最多约 60 s 退避且没有总时长上限；与 H1 的"≤5 次尝试 / ≤150 s"不同。
选项
(a) 直接改 MAX_STARTUP_RETRIES=4 并加总时钟——影响手动路径，R-001 风险；(b) 自动会话独立预算，宿主通过许可接口接入，手动路径不变；(c) 自动会话不重试，一次失败就停——太脆。
决定
(b)。独立 AutoConnectBudget：5 次尝试、150 s 硬截止、退避 2/4/8/16 s、剩余不足 20 s 不再开新尝试。宿主每次重启前申请许可；手动路径不申请。
后果
慢失败最坏 3 次/149 s，快失败 5 次/55 s，恒满足约束；多一层许可调用与一个 sessionId 传递；两套预算并存需要文档说明（本 ADR）。
复审条件
H3 显示 150 s 仍让车主等待过久（可降到 90 s，需回 H1 因 NFR-002 变更）；或宿主重构后合并为一个预算。

ADR-004 失败静默：自动会话绝不弹阻塞对话框

状态：已决定 · 影响：FR-007、NFR-011 · 关联 R-006、AC-009/025

背景
现有 connect() 在热点关闭时弹 carHotspotOffDialog()（三按钮 AlertDialog）。自动触发在驾驶中发生，弹窗会遮挡/打断。
选项
(a) 复用现有 dialog；(b) 自动会话改为 Home/启动界面 inline notice + 单一重试；(c) 完全静默，只在设置里留日志——车主不知道发生了什么。
决定
(b)。自动分支不进 carHotspotOffDialog()，直接终态并渲染 inline notice；手动分支保留既有 dialog（不回归）。
后果
R-006 设计层关闭；需要新的 notice 布局与"打开车机热点设置"动作；测试要分别断言自动无 dialog、手动有 dialog。
复审条件
如果 H3 发现车主注意不到 inline notice（SM-002 不达标），可加"下一次打开时提醒"，仍不得用阻塞框。

ADR-005 无 ADB 时的行为：降级阶梯而不是"不支持"

状态：已决定 · 影响：FR-002/005、G-4 · 关联 R-003

背景
自动开热点依赖 WRITE_SETTINGS（ADB 授予）或固件支持；大多数普通车主没有 ADB。若把"自动连接"等同于"自动开热点"，功能对多数人不可用。
选项
(a) 只支持有 ADB 的车机；(b) 无 ADB 也自动连接，但要求热点保持开启；(c) 尝试用非公开 API 强开热点。
决定
(b)：四档阶梯（A 增强 / B 标准 / C 基础 / D 手动），C 档仍保证"打开 DiPlay 即自动连接"；不碰非公开 API。
后果
功能对无 ADB 用户也可用（SM-001 仍有意义）；需要"热点保持开启"的清晰文案与一次性提示；R-003 依赖 H3 验证各固件档位。
复审条件
若某 DiLink 固件在 Tier B 下仍频繁失败，需把该固件列入已知限制（docs/COMPATIBILITY.md），不扩权限。

ADR-006 与既有连接路径共存：附加协调层，不替换

状态：已决定 · 影响：FR-014、DG-6 · 关联 R-001

背景
已有 connect(wireless)、CarPlay 宿主重试、四种后端。重写会引入巨大回归面（R-001/R-002 S1）。
选项
(a) 重构连接栈为统一状态机；(b) 新增"门禁 + 会话"协调层，出口仍调既有 connect(true)；手动路径不变。
决定
(b)。协调层只回答"要不要连、连谁、还能试几次"，连接本身仍由既有控制器完成。手动路径以 sessionId=null 完全绕过新预算。
后果
回归面可控（改动集中在入口与宿主重试许可）；两套预算需要 ADR-003 的说明；未来若重构连接栈，协调层可整体下沉。
复审条件
宿主重构或引入统一连接编排时，合并预算与状态机；本 ADR 失效并重写。

ADR-007 休眠唤醒用进程内运行时接收器

状态：已决定 · 影响：FR-009、C-1/C-2 · 关联 R-004、AC-012

背景
Android 的 ACTION_SCREEN_ON 不能由清单接收器接收；新增前台服务常驻违反 FR-009 边界；轮询违反 NFR-003。
选项
(a) 新增常驻前台服务；(b) 清单注册（不可行）；(c) 进程内 registerReceiver，进程存活期间有效；(d) 不做唤醒触发。
决定
(c)。只在总开关开且有首选时注册，applicationContext、幂等、关闭即注销；进程被杀后不承诺（A-004），由 T-2 兜底。
后果
零新组件、零新权限、零轮询；能力上限受系统冻结/后台启动限制，必须写入文案与 R-004；测试要覆盖注册幂等与注销。
复审条件
若 H3 证明目标固件在休眠时冻结进程导致接收器不可用，需评估前台服务方案 → 回 H1（FR-009 边界变化）。

ADR-008 诊断只用枚举/整数，拒绝自由文本

状态：已决定 · 影响：NFR-009/004 · 关联 R-008

背景

复审条件
若 H3 排障确实需要设备名，必须改为"脱敏后的固定映射"，并重新评估 NFR-004。
